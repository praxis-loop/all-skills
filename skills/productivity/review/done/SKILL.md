# Done — 会话复盘与沉淀

## 目的

在用户与 AI agent 完成一段工作后手动触发，对**本次会话**做结构化复盘，帮助：

1. 让用户下次**更快提问**（产出/更新提问模板）；
2. 把真正长期有用的洞察**沉淀进 memory**，让 agent 越来越懂这个项目和这个人；
3. 指出用户暴露的**知识短板**并给补强方向；
4. 识别**跨会话反复出现的固定流程**，建议提炼成新 skill。

核心哲学：**先判断"值不值得沉淀"，再决定要不要写。空手而归也是合法结果——宁可不写，不硬凑。** 永远先书面汇报、用户逐项拍板、批准后才落地。

## 输入

- 手动触发（`/done` 或"复盘这次会话"）。通常在会话末尾运行，agent 已持有当前会话上下文。
- 环境：`$CLAUDE_CONFIG_DIR` 已设置；当前项目 `cwd`；当前 session id（用于扫描历史会话时排除自身，可从 scratchpad 路径或上下文取得）。
- 依赖 `python3` 运行 `scripts/scan-sessions.py`。
- 无需用户额外提供材料；如缺 session id，可不排除，扫描结果里当前会话会与上下文重复，忽略即可。

## 工作流程

1. **读当前会话**：从上下文回顾本次会话——用户目标、走过的弯路、反复澄清点、卡点、用户表现出的偏好与知识盲区。板块 1–4、6 主要基于此。
2. **扫历史会话**（板块 5 用）：运行
   ```bash
   python3 scripts/scan-sessions.py --exclude <当前 session id>
   ```
   （`--config-dir` 默认取 `$CLAUDE_CONFIG_DIR`，`--cwd` 默认当前目录。）它输出各历史会话的用户意图 JSON。对意图做主题聚类，找**跨会话重复**的流程。
3. **查重**：提议新 skill 前，比对本仓库 `skills/**` 与已安装的 `$CLAUDE_CONFIG_DIR/skills/`，避免重复造已存在的能力。
4. **逐板块判断**：对六个板块逐一套用 `references/judgement-gates.md` 的闸门；不够格的板块直接写"本次无"，不硬凑。
5. **生成 debrief**：按下面六板块输出，每项末尾标 `[建议] …` 或 `[无需动作]`。
6. **等用户拍板**：呈现后停下，等用户指明要落地哪几项（例："2、3 做，其余跳过"）。**未批准前不写任何文件。**
7. **执行批准项**：
   - 写 memory → 复用项目 `memory/` 系统，遵守 `MEMORY.md` 索引规范（同主题则更新而非新建）；类型用 `user`/`feedback`/`project`/`reference`。
   - 更新提问模板 → 写入/更新模板文件。
   - 建议 skill 被采纳 → 引导进入本仓库 `docs/SKILL_GUIDE.md` 的新增 skill 流程（本 skill 不直接造 skill）。

## 输出要求

六板块 debrief（Markdown），每项带动作标记：

1. **本次会话概述** — 一句话：用户想解决什么、最终怎么解决。无落地动作。
2. **更快的开场提问** — "如果一开始这么说会更快"（缺失上下文/没说清的约束/反复澄清点）。确有可复用改进 → `[建议]` 产出/更新提问模板；否则"本次无明显改进空间"。
3. **可沉淀的项目记忆** — 只挑跨会话仍成立、且代码/git 查不到的洞察。每条说明**为什么值得沉淀**，`feedback`/`project` 类补 `**Why:**` 与 `**How to apply:**`。无则"本次无"。
4. **知识短板与补强建议** — 指出本次暴露的知识薄弱点 + 该补哪块知识的具体方向。**必须引用本次会话的证据**；给方向不说教；长期短板可 `[建议]` 写成 `user` 类 memory。无信号则"本次无"，不无端评判。
5. **可提炼的固定流程 → skill** — 基于历史会话聚类 + 本次会话。够格须同时满足：① 在 ≥2 个会话出现且**列出是哪几个会话**（id/日期/简述）；② 步骤可复用；③ 无同类 skill。给出候选 skill 名、解决的重复问题、跨会话证据。**只提议不自动创建。**
6. **其他发现** — 用户没提到但有价值的模式（反复踩的卡点、常用工具/命令习惯、协作偏好）。够格的归入板块 3。

判断闸门细则见 `references/judgement-gates.md`。

## 检查项

- 六个板块都已给出（不适用的显式写"本次无"，不留空）。
- 板块 3/4 每条建议都附了理由/证据；板块 5 每个 skill 候选都列了 ≥2 个会话的证据。
- 呈现 debrief 后**已停下等待用户拍板**，未擅自写入。
- 写 memory 前已查重，遵守 `MEMORY.md` 索引规范（更新优先于新建）。
- `scan-sessions.py` 正常返回（`warnings` 为空或已说明）。

## 边界

- **未经用户批准，不写入任何 memory / 模板 / 文件**（与仓库 SKILL_GUIDE 的写入前确认要求一致）。
- 本 skill **不直接创建 skill**，只提议；创建走仓库 `docs/SKILL_GUIDE.md` 流程。
- **不做全自动落地**，不做定时/自动触发，纯手动 `/done`。
- 不通读历史会话的 assistant 输出与工具调用，只取用户意图聚类（省 token）。
- 知识短板板块要**基于证据、对事不对人**；无明确信号宁可不提。
- 不使用仓库内密钥或机器专属路径；脚本路径全部参数化。
