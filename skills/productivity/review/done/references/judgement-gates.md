# 判断闸门（各板块"够不够格沉淀"的标准）

通则：**宁可不写，不硬凑。** 每个板块都允许输出"本次无"。所有落地动作都需用户先批准。

## 板块 2 · 更快的开场提问

产出/更新提问模板的条件：

- 本次会话确实出现了"因为一开始没说清而多走的弯路"，且这种改进**可复用到以后同类请求**。
- 能具体指出：缺了哪个上下文 / 哪条约束没讲 / agent 反复澄清了什么。
- 不够格：纯属本次一次性的细节，抽象不出可复用的提问结构 → 写"本次无明显改进空间"。

## 板块 3 · 可沉淀的项目记忆

一条洞察够格写进 memory，须同时满足：

- **跨会话仍成立**：不是只对这次任务有效的临时状态。
- **代码/git 查不到**：能从仓库、提交历史、CLAUDE.md 直接得知的，不重复沉淀。
- **对未来会话有用**：能让 agent 下次少问、少错。

类型与写法（与用户 CLAUDE.md 的 memory 规范一致）：

- `user`：用户是谁（角色、专长、偏好）。
- `feedback`：用户给的工作方式指导（含纠正与确认），正文补 `**Why:**` 与 `**How to apply:**`。
- `project`：正在进行的工作、目标、约束，且非代码可推知；相对日期换成绝对日期，正文补 `**Why:**` 与 `**How to apply:**`。
- `reference`：外部资源指针（URL、看板、工单）。

写入规则：先查重，同主题**更新已有文件**而非新建；写完在 `MEMORY.md` 加一行指针。

## 板块 4 · 知识短板与补强建议

提出的条件：

- **必须有本次会话的证据**：如反复问同一概念、对某工具/机制心智模型明显有偏差、同一处来回澄清、被基础问题卡住。引用具体是哪一处。
- **给方向不说教**：指出薄弱点 + 建议补强的**具体知识块/资料方向**（某机制、某工具的某部分、某文档），不写笼统的"要多学习"。
- **对事不对人**：描述知识缺口，不评判个人能力。
- 长期、跨会话反复出现的短板 → 可建议写成 `user` 类 memory（让 agent 以后主动照顾表达深度）。
- 无明确信号 → "本次无"，不要为凑板块而制造评判。

## 板块 5 · 可提炼的固定流程 → skill

一个流程够格被建议做成 skill，须**同时**满足：

1. **跨会话证据**：在 ≥2 个会话里出现过，且列出是哪几个会话（session id / 日期 / 一句话简述）。
2. **可复用**：步骤相对固定、有清晰的输入与输出，不是一次性探索。
3. **无重复**：本仓库 `skills/**` 与已安装 `$CLAUDE_CONFIG_DIR/skills/` 里没有同类能力。

建议内容：候选 skill 名（小写短横线）、它解决的重复问题、跨会话证据、以及"下一步走 `docs/SKILL_GUIDE.md` 新增流程"。**只提议，不自动创建。**

## 板块 6 · 其他发现

- 提本次观察到、但用户没主动提及、且对以后协作有价值的模式。
- 够格沉淀的（跨会话成立），归入板块 3 的 memory 建议并走板块 3 的闸门。
- 只是本次一次性的现象 → 提一句即可，不落地。
